Discussions as Your Community Front Door

How to enable Discussions, set up categories, pin canonical threads, and convert between issues and discussions as conversations change shape.

Shubham Anandani·Published October 15, 2026·3 min read

Problem

Issues should track work. Discussions suit open-ended questions, ideas, and announcements. Discussions supports categories with different formats, pinned threads, accepted answers, upvotes, and conversion between issues and discussions. Defining these early keeps the work queue clean and reduces duplicate issues.

Options and trade-offs

  • Categories: group conversations by purpose. Each category can have a format such as announcement, Q&A, or open-ended. Check the current category limit in the docs.
  • Pinning: highlight canonical threads such as the FAQ or onboarding guide.
  • Accepted answers and upvotes: surface solutions and priorities. They need moderator attention to stay useful.
  • Conversion: move a thread from issue to discussion, or back, when its nature changes.

My take

Keep a small set of categories, pin the threads newcomers need first, and use a category form for Q&A so questions arrive with the details needed to answer them.

Decision lens: new-contributor friction and review latency.

Example setup: categories for Announcements, Q&A, and Ideas. The FAQ and a first-thirty-minutes guide are pinned. The Q&A category uses a form that asks for version, steps to reproduce, and expected versus actual behavior.

Template

.github/DISCUSSION_TEMPLATE/qna.yml: a category form with prompts for version, steps, expected behavior, and actual behavior.

Welcome post: the purpose of the space, the code of conduct, and the rules for converting between issues and discussions.

Category setup: Announcements restricted to maintainers, and Q&A with accepted answers enabled.

Checklist

  1. Enable Discussions and create categories.
  2. Pin the FAQ and onboarding threads.
  3. Add a Q&A category form.
  4. Write down the conversion rules between issues and discussions.
  5. Review the category setup each quarter.

Common mistakes

  • Running without categories, which makes threads hard to find.
  • Not pinning canonical answers, so the same questions keep coming back.
  • Never converting issues, so the work queue fills with general chat.

Where this doesn't apply

  • Organizations required to use an external forum or ticketing system.

How to get involved

  • Good first issue: propose a new pinned FAQ entry.
  • Discussion: what should the Q&A form ask first?
